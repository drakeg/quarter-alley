# Community, Discussions, and sponsorships

## GitHub Discussions

Community conversations: https://github.com/drakeg/quarter-alley/discussions

Suggested categories to configure in GitHub Discussions settings:

| Category | Format | Purpose |
| --- | --- | --- |
| Announcements | Announcement (maintainers only) | Releases, new cabinets and service updates |
| General | Open-ended discussion | Arcade conversation |
| Ideas | Open-ended discussion | New game concepts and improvements |
| Q&A | Question / answer | Gameplay and setup questions |
| Show and tell | Open-ended discussion | Scores and gameplay stories |
| Polls | Poll | Prioritize features and game concepts |

The repository provides discussion templates for game ideas, questions and player feedback. GitHub category names and category IDs are configured in GitHub's Discussions settings, not in these template files. If a template does not appear, ensure its intended category exists and check GitHub's supported template naming and category mapping.

Use Issues for actionable, reproducible bugs and development work. Use the private contact form for account, payment, refund and other personal matters. Never post secrets or payment information publicly. Follow the project's originality rules.

## Sponsorships

The repository's GitHub Sponsors option is enabled by the owner. **Enabling the option alone does not establish an active, approved payout profile.** Confirm the funding destination and eligibility before adding a `.github/FUNDING.yml` file. Do not publish an unverified payment link.

Potential supporter benefits, subject to later implementation and policy review:
- Recognition in a dedicated supporter section (opt-in only).
- Voting on upcoming original games through Discussions.
- Early previews and release notes.

Do not promise unlimited gameplay, paid tokens, special account access, or financial benefits until they are actually implemented. Sponsorships are distinct from Stripe token purchases.

## Moderation

Keep discussions civil and relevant; no harassment, spam, personal data, copyrighted game assets, or credential sharing. Report security vulnerabilities through SECURITY.md, not public Discussions. Maintainers may move actionable suggestions into BACKLOG.md or GitHub Issues. A community suggestion is not a commitment to ship.
